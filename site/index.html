Healthcare, medical-device safety

Spot the medical devicesmost likely to be recalled.

RecallRadar ranks types of medical devices by their chance of a serious FDA recall in the next 12 months. On 2023 to 2024 data it never saw, it scored 0.959 out of 1.0 at ranking, versus 0.928 for ranking by past recalls alone.

Try the demoSee how it works

The problem

More reports can mean more users, not more danger.

When a medical device has a serious problem, the FDA can order a recall. In 2021, for example, Philips recalled millions of sleep apnea breathing machines because a foam part inside could break down. Hospitals and device makers want that kind of warning as early as possible.

Patients, doctors and device makers file public problem reports with the FDA. But a popular device gets more reports simply because more people use it. So RecallRadar asks a simple question: do the patterns in those reports point to the next serious recall better than just counting them?

What the model reads

One device type. One quarter. One score you can check.

How many problem reports came in, the share that involved an injury or a death, how fast reports are growing, how many companies make that type of device, and its past recalls.

What you get

A ranked list with a reason for every flag.

The FDA names each type of device with a three-letter code, such as FPA. Each quarter, the model gives every device type a risk score from 0 to 1 (higher means more likely to be recalled) and ranks them. Next to each flag, it names the signal that pushed the score up, such as a recent recall.

The results are saved in this page, so you can try it in 30 seconds with no account. No chatbot decides what gets flagged. Flags come only from the trained model and fixed, tested code.

Tested on 2023 to 2024, data it never saw

It ranks better than counting reports or past recalls.

The test covered 400 device types and quarters, and 187 of them (47%) really did have a serious recall within 12 months. The ranking score runs from 0 to 1, where 1.0 is a perfect ranking, so higher is better.

Counting reports scored 0.491, barely better than random guessing on this test. Because about half the cases had a recall, the model and the past-recalls method both got all 50 of their top 50 picks right. The ranking score is what separates them.

How it works

Five steps, each one checked.

The model stays small enough to explain. The testing is strict enough to catch the model accidentally peeking at the answer. Those checks run as code every time, not just as a promise on this page.

  1. Collect the reports

    Pull 40 quarters (10 years) of public FDA problem reports and serious recall records.

  2. Sum up each device type

    For each device type and quarter, record the report patterns, its past recalls and the time since its last recall.

  3. Mark what happened next

    Note whether a serious recall started in the next 12 months. An automatic check proves the model only sees information from before that window.

  4. Learn, then explain

    Build the model on data through 2021, tune it on 2022, and test it on 2023 to 2024. Each flag gets a plain reason.

  5. Compare honestly

    Score it against two simple methods: ranking by number of reports and ranking by past recalls.

Technical details

Data

openFDA Device Adverse Event API (MAUDE) for event counts and openFDA Device Recall API for Class I or II recall labels, both CC0 and keyless. 40 quarters, 2015 to 2024, top 50 product codes by report volume per quarter: 2,000 code-quarter rows, 127 unique codes.

Features and label

report_count, injury_share, death_share, report_growth, manufacturer_count, prior_recall_count (previous 12 months) and time_since_last_recall_days. Label is 1 when a new recall starts for the code in the next 12 months. A leakage assertion (and test) requires every feature_date_max to precede label_window_start.

Model

One LightGBM classifier (150 trees). Time split: train through 2021 (1,400 rows), validate on 2022 (200), test on 2023 to 2024 (400 rows, 187 positive). The reason string is the largest positive SHAP contribution from TreeExplainer. No LLM call anywhere.

Metrics

PR-AUC (average precision): 0.959 vs 0.928 for the prior-year recall-count baseline and 0.491 for raw report count. Model 1,000-resample bootstrap 95% CI: 0.934 to 0.977. Precision@50 saturates at a 47% positive rate: 50/50, 50/50, 35/50. The demo chart is per-quarter precision@10, model vs volume.

Limitations

Only the top 50 volume codes per quarter, so not full surveillance. MAUDE is noisy, product-code definitions change, and a recall label is not causal. The model ties the prior-recall baseline at precision@50. No production MLOps, monitoring, model registry or regulated approval workflow.
